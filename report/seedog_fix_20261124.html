一、根因（已确认）

  • 不是 GitHub Actions 停了：11-16～11-24 每天定时与手动触发均 success，最近一次 11-24 的两次运行 45314841230 / 45315085620 均成功。
  • 是 seedog.cc 的 Cloudflare 按 IP 信誉挑战：本地与 CI 出口直连均 HTTP 403 + Just a moment...；公共代理出口（allorigins / codetabs / corsproxy）同样被挑战。生成器命中挑战特征后跳过该源、保留旧 feed。
  • Actions 为什么全绿：生成器步骤设了 continue-on-error: true，单源被跳过不报错；XML 内容零变化 → 走「XML 无变化，跳过提交」分支，页面上完全看不出停更。
  • 站点本身正常更新：修复时用浏览器抓到最新 20 条（首条「繁华落尽」），证明内容与解析规则都没问题。

二、方案 C：seedog 改浏览器抓取（换接口，内容不变）

探测结论：seedog 没有原生 RSS/API（/atom.xml、/feed.xml 均 404，sitemap 被挑战），RSSHub 无路由，所有代理出口都被 CF 拦。唯一可行通道是真实浏览器 JS——Edge 与 Playwright Chromium 均一次通过（200 / 20 cover / 无挑战）。

文件改动影响范围
src/sources.jsonseedog 条目新增 fetch:"browser"、wait_selector:".cover"、settle:2，并加 note 说明仅 seedog 一个源；其它源配置一字未动
.github/workflows/generate.yml新增「Install Playwright」步骤（pip install playwright + playwright install --with-deps chromium），设 continue-on-error安装失败只让该源跳过，不影响其它源
内容、专用解析器 parse_seedog、订阅地址 https://ghaner.github.io/WebFeedGitHubGenerater/seedog.xml 全部未变——你的阅读器无需任何改动。

三、方案 D：停更告警（不再「假成功」）

.github/workflows/generate.yml 末尾新增「Check feeds freshness」步骤：读每个 *.xml 的 <lastBuildDate>，若某源连续 ≥3 天 未成功生成（说明被反爬/改版拦截、旧 feed 被保留），同时输出：

  • ::warning:: 注解 → Actions 步骤页直接可见黄色警告
  • Job Summary 表格 → 汇总每个源的「最后成功时间 / 距今天数」

阈值走仓库变量 STALE_DAYS（默认 3）。告警不阻断流程、不影响订阅。

副作用提示：首次跑 CI 时，若其它源也因当天抓取失败而停留在旧日期，会一起告警——这正是目的：让所有停更都显形，而不是只盯着 seedog。

六、避坑记录

  • seedog 的 CF 是按 IP 信誉判定，不是 UA 问题——换 UA、加 header、走公共代理全部无效；只有真实浏览器 JS 能过。
  • 本项目其它站（yszzq / cctv / xuangutong / kkys14）走直连或 cookie，不要因为 seedog 改用浏览器就给所有源都加 fetch:browser——会平白拖慢整条流水线。
  • workflow 的 Playwright 安装步骤设了 continue-on-error：装不上时 seedog 会跳过、保留旧 feed，此时 D 的告警会在 3 天后提醒你，不会静默。
