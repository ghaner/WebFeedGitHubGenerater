二、怎么判型的（先判型，再选型）

curl 直连页面→ HTTP 200 / 30KB，有 SSR 内容→ 但主列表处是 guest-login-prompt→ 换浏览器监听 XHR→ 锁定 featured 接口
观察结论
页面 <html data-n-head-ssr>，body 里有完整导航与侧栏 Nuxt 服务端渲染，不是纯 SPA 空壳，所以先不必上 Playwright
「精选更新」区域只有一个 guest-login-prompt，文案「登录后可查看全部内容」 登录墙：DOM 里永远拿不到条目 —— 找 item_block 或换 fetch:"browser" 都是死路
侧栏「原创热文」有 10 条 SSR 文章，但不是主列表 只能作为旁证（文章链接形如 /article/<id>），不足以当数据源
无头浏览器监听全部 XHR，看到 baoer-api.xuangubao.com.cn 的公开接口 确认存在公开接口层，改用 parser:"json" 直连接口
这个站没有反爬挑战（既不是 Cloudflare 也不是 cdndefend），所以不需要 cookie 通道， 也不需要 cookie_recovery。真正的障碍只有登录墙，而登录墙挡的是 DOM、不挡接口。

四、代码改动（两处，约 15 行，向后兼容）

改动位置作用
date_ts 字段选项 src/generate_feed.py · parse_json() 把秒级 Unix 时间戳按 tz 换算成北京时间再写 pubDate。 必须显式换算：CI 跑在 UTC，若用本地时区会整体偏 8 小时
字段级 base src/generate_feed.py · parse_json() 与 parser:"generic" 行为对齐：{"key":"id","abs":true,"base":".../article/"} 即可把纯数字 ID 拼成详情链接
新增配置源 src/sources.json xuangutong 一条，含 items_path、字段映射与卡片模板
回归验证：重跑 cctv_jkzl（同样用 parser:"json" 但走 date 分支）， 仍为 50 条、pubDate 格式不变、link 与简介字段齐全，结构零回归； 首条日期从 11-13 变为 11-15 是栏目本身出了新一期节目，不是代码变化。

七、风险与后续可做的

风险表现与对策
接口变更 / 加鉴权 生成器提取 0 条时会跳过该源并保留旧 feed，订阅不中断；届时重新抓一次 XHR 即可。
每日一次刷新太慢 该站日内更新频繁（每小时数条）。若要更及时，可把 generate.yml 的 cron 改成每 2 小时一次（0 */2 * * *，UTC）。
只想要某个栏目 把 subj_ids 收窄即可，例如只看研报就写 subj_ids=581。
想要正文摘要 需登录态 cookie 才能取，属于另一套方案（cookie 通道 + 逐篇抓取），会显著拉长生成时间，暂未做。
